# 🌍 Куда поставить бэкенд (вместо Railway)

Railway лимит исчерпан — вот проверенные альтернативы на **октябрь 2026**.
Наш бэкенд — это обычный постоянно работающий Node-процесс
(`npm run build` → `npm start` = `node server/start.js`), поэтому нужен хостинг,
который **не засыпает** и даёт **PostgreSQL**.

---

## 📊 Короткое сравнение (бесплатные тарифы)

| Хостинг | Спит? | Бесплатная БД | Проблемы |
|---------|-------|---------------|----------|
| **Northflank** ✅ | **Нет (always-on)** | 1 БД включена | Лимиты по ресурсам, но для нас хватает |
| **Render** | Да — через 15 мин простоя (~1 мин на «пробуждение») | Есть, но **удаляется через 30 дней** | БД надо брать отдельно (Neon/Tiger) |
| **Koyeb** | Нет | Есть, но только **5 часов compute/мес** | БД почти сразу «съедает» лимит |
| **Zeabur** | Да — авто-сон | Есть | Free-план засыпает |
| **Fly.io** | Нет | Нет бесплатной БД | Бесплатного тарифа больше нет |

**Вывод: ставь на Northflank** — он не засыпает, БД включена, и это тот же
принцип, что у Railway (deploy из GitHub + переменные + база).

## ✅ Вариант A (рекомендую): Northflank

Бесплатный план **Developer Sandbox**: 2 сервиса + 1 БД + 2 cron, **always-on**.

### 1. Аккаунт и проект
1. [northflank.com](https://northflank.com) → **Sign up** (через GitHub).
2. **Create Project** → назови как угодно (например `biznes-baza`).

### 2. Залей код на GitHub
Если ещё не залил — см. шаг 1 в [RAILWAY.md](RAILWAY.md) (`.env` не коммитим).

### 3. Создай сервис (приложение)
1. В проекте: **Create Service** → **Combined Service** (или **Deployment Service**).
2. **Repository:** подключи GitHub → выбери репозиторий → ветка `main`.
3. **Build type:** `Buildpack` (Nixpacks) — он сам прочитает `package.json`.
   - **Build command:** `npm install --include=dev && npm run build`
   - **Start command:** `npm start`
4. **Port:** `4000`, тип `HTTP`.
5. Пока не деплой — сначала база.

### 4. Создай базу PostgreSQL
1. В проекте: **Create Addon** → **PostgreSQL**.
2. План — бесплатный (`Sandbox`/`Free`), тип `PostgreSQL`.
3. Назови, например, `biznes-db`. Дождись статуса **Running**.

### 5. Свяжи базу с сервисом
1. Открой БД → **Connection details** → скопируй **Connection string**
   (внутренний адрес, обычно с `@<db>.<project>:5432`).
2. В сервисе → **Environment** → **Add variable**:
   - `DATABASE_URL` = строка подключения из БД
   - `CORS_ORIGIN` = `*` (или свой домен)
   - `ADMIN_LOGIN` = `admin`, `ADMIN_PASSWORD` = свой пароль
3. **Deploy**.

### 6. Домен
1. Сервис → **Networking** / **Ports** → **Add public port** / **Expose**.
2. Получишь адрес вида `https://<имя>-<проект>.northflank.app`.
3. Открой `https://<адрес>/api/health` — должно быть
   `{"status":"ok","database":"connected"}`.

В логах после деплоя ищи:
```
[seed] Tayyor: 11 a'zo, 482 biznes yozuvi, 110 Instagram biznes
```

## 🟣 Вариант B (просто, но с нюансом): Render

Интерфейс максимально похож на Railway, но **бесплатная БД удаляется через 30 дней**,
а веб-сервис засыпает. Поэтому: приложение — на Render, база — на Neon/Tiger Cloud.

1. [render.com](https://render.com) → **New** → **Web Service** → подключи репозиторий.
2. Настройки:
   - **Build Command:** `npm install --include=dev && npm run build`
   - **Start Command:** `npm start`
   - **Environment:** `Node`
   - **Instance type:** Free
3. **Environment Variables:** `DATABASE_URL` = строка из Neon (см. ниже), `CORS_ORIGIN=*`.
4. **Create Web Service**.
5. Готовый файл `render.yaml` в корне проекта можно использовать как
   **Blueprint** (New → Blueprint) — тогда Render настроит всё сам.

> Минус: первый запрос после сна может грузиться ~1 минуту.

## 🐘 Бесплатный PostgreSQL (вместо БД хостинга)

Хорошо подходят, если БД на хостинге отсутствует или истекает:

| Сервис | Бесплатно | Срок годности |
|--------|-----------|---------------|
| **Neon** | Serverless Postgres, ветвления | **Без ограничения по времени** |
| **Tiger Cloud** | 2 сервиса по 750 МБ, без карты | **Без ограничения по времени** |
| Render Postgres | 1 ГБ | ⚠️ Удаляется через 30 дней |

Наши данные крошечные (сотни записей), так что 500–750 МБ хватит с запасом.

**Как подключить (общий шаг):**
1. Регистрируешься, создаёшь Postgres, копируешь **Connection string**
   (обычно `postgresql://user:pass@host/db?sslmode=require`).
2. Добавляешь его в переменные сервиса как `DATABASE_URL`.
3. Deploy — при старте `server/start.js` сам выполнит `prisma db push` и seed.

## 🔧 Настройки, которые нужны любому хостингу

| Параметр | Значение |
|----------|----------|
| Build command | `npm install --include=dev && npm run build` |
| Start command | `npm start` |
| Порт | `process.env.PORT` (сервер сам читает; локально 4000) |
| Обязательные переменные | `DATABASE_URL` |
| Логин админа | `ADMIN_LOGIN` (по умолчанию `admin`), `ADMIN_PASSWORD` (по умолчанию `admin123`) |
| Необязательные | `CORS_ORIGIN`, `VITE_API_URL` (только если фронт отдельно) |

**Код менять не нужно** — всё уже готово: сервер сам применяет схему и
засевает базу при первом запуске. Страница входа — `/login`.

## 💡 Ещё вариант: всегда бесплатный сервер (своими руками)

**Oracle Cloud Always Free** даёт бесплатную ARM-машину (VM) навсегда.
На неё можно поставить Node + PostgreSQL вручную. Плюс — никаких лимитов и
засыпаний; минус — нужно администрировать сервер самому (обновления, firewall, HTTPS).
Если готов возиться — это самый «бесплатный навсегда» путь.

## ⚠️ Общие подводные камни

1. **Хостинг, который «засыпает»**, при пробуждении заново запускает
   `start.js` → повторный `prisma db push` (несколько секунд). Это нормально.
2. **Бесплатную БД с ограниченным сроком** (Render — 30 дней) потеряешь вместе
   с данными — используй Neon/Tiger.
3. **Не коммить `.env`** — секреты только через панель «Environment».
4. Проверяй `https://<домен>/api/health` → `"database":"connected"` — это признак,
   что бэкенд подключился к базе. Если `"fallback"` — значит `DATABASE_URL` не задан
   или недоступен, и сервер отдаёт данные из `prisma/seed-data.json`.
